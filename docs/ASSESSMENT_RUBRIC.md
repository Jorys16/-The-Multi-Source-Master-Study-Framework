# Assessment and Mastery Rubric

## Suggested weights

| Component | Weight |
|---|---:|
| Guided labs and practical exercises | 20% |
| Independent assignments | 15% |
| Knowledge checks and quizzes | 10% |
| Engineering practice and code review | 15% |
| MVP sprint milestones | 20% |
| Final capstone and technical defense | 20% |

These weights are guidance for self-assessment, not an external academic credential.

## Four competency levels

| Level | Description | Evidence |
|---|---|---|
| 1 — Familiarity | Recognizes terminology and can follow a tutorial. | Notes, guided exercise |
| 2 — Working understanding | Explains the model and modifies a known example. | Diagram, modified lab, quiz |
| 3 — Independent implementation | Builds, tests, and debugs a solution with limited guidance. | Independent assignment, PR, test results |
| 4 — Engineering judgment | Chooses an approach, explains trade-offs, secures it, measures it, and handles failure. | Architecture decision, evaluation, threat model, operational evidence |

Do not label a topic “mastered” from a quiz or course completion alone.

## Review dimensions

1. Requirements and product thinking.
2. Correctness and implementation quality.
3. Testing, debugging, and edge cases.
4. Data quality and AI evaluation.
5. Security, identity, and least privilege.
6. Documentation, delivery, and communication.

## Weekly exit check

- Can I explain the concept without notes?
- Can I draw its architecture or behavior?
- Can I start a small implementation from a blank file?
- Can I test an invalid or adversarial case?
- Can I debug one failure and explain its root cause?
- Have I used it in the capstone or another practical artifact?
- Can I explain limitations and alternative approaches?
