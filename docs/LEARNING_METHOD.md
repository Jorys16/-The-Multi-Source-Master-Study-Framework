# Learning Method: Build Mental Models, Not Just Familiarity

## The six-pass method

Every important concept is studied through multiple representations:

1. **Intuition / visual:** Find an analogy, animation, diagram, or concrete story. Draw the idea.
2. **Formal model:** Learn exact definitions, assumptions, mechanisms, and boundaries from a structured course and authoritative reference.
3. **Worked example:** Trace a small example step by step. Predict the next state before running it.
4. **Implementation:** Build a minimal version from a blank file or schema. Change an input or requirement.
5. **Debug / verify:** Create failure cases, inspect errors, test assumptions, fix the root cause, and add regression coverage.
6. **Retrieve / teach back:** Close notes and explain the concept, draw it, and solve a new problem.

## Conceptual redundancy rule

Use three complementary sources, not ten random tutorials:
- One primary structured course.
- One alternate visual or conceptual explanation.
- One authoritative documentation/specification source.

Then use a hands-on lab. A second explanation is useful when it changes your mental representation, not merely because it repeats the same content.

## Spaced retrieval

| Timing | Review |
|---|---|
| Same day | Write a plain-English explanation from memory |
| +1 day | Redraw the diagram and answer three questions |
| +3 days | Solve a new example or edge case |
| +7 days | Use the concept in a project or lab |
| +14 days | Teach it back and compare with an adjacent concept |
| +30 days | Include it in a cumulative exercise |

## Mastery gates

A topic is not complete because a video was watched or a quiz was passed. Require:
- Explain the concept without notes.
- Draw the execution, data, or trust flow.
- Implement a small version independently.
- Test normal, edge, error, and denied-access cases when relevant.
- Diagnose one failure and explain the root cause.
- Apply the idea to the capstone.
- State limitations and trade-offs.

## AI coding assistant rules

- Attempt the problem before asking for a complete answer.
- Ask for hints, explanations, test ideas, and code review rather than copy-paste solutions.
- Read and test every generated line you keep.
- Never commit credentials, personal data, or private employer data.
- Be able to explain the code in a live walkthrough.
